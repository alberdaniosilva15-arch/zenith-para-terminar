SUMÁRIO EXECUTIVO
------------------
O Zenith Ride é uma aplicação completa de mobilidade urbana (tipo Uber/Bolt)
desenhada para Luanda, Angola. O MVP está FUNCIONAL com as seguintes
funcionalidades core implementadas:

  ✓ Autenticação (email + Google OAuth)
  ✓ Sistema de corridas completo (pedido → match → aceitar → rastrear → completar)
  ✓ Sistema multi-papel (Passageiro, Motorista, Dono de Frota, Admin)
  ✓ Pagamento via Multicaixa Express (mobile money angolano)
  ✓ IA assistente (Kaze) multi-provider
  ✓ Validação de documentos por IA (Sentinel Vision)
  ✓ Chamadas VoIP (Agora.io)
  ✓ Sistema de segurança (botão pânico, deteção de gritos, SMS emergência)
  ✓ Dashboard Admin com IA
  ✓ Gestão de frota
  ✓ Contratos escolares/familiares com monitorização parental
  ✓ Gamificação (Zenith Score, níveis, quilómetros grátis)
  ✓ App mobile (Capacitor para Android)

NOTA: O app está a correr em http://localhost:5173

2.1 SISTEMA DE CORRIDAS
------------------------
  Fluxo completo:
    1. Passageiro define origem/destino
    2. Sistema calcula preço por zona (preço fixo + surge dinâmico)
    3. Matching de motoristas via H3 hexagonal (resolução 9, ~150m)
    4. Motorista recebe notificação e aceita/rejeita
    5. Rastreamento em tempo real durante a corrida
    6. Detecção de desvio de rota
    7. Pagamento automático ao finalizar
    8. Avaliação do motorista

  Código relevante (rideService.ts):
    - Criar corrida: createRideRequest()
    - Matching: expandH3Search() com anéis crescentes (2→4→7)
    - Subscrever corridas: subscribeToRideUpdates()
    - Detecção de desvio: checkRouteDeviation()

2.2 SISTEMA DE PREÇOS
-----------------------
  Motor de preços híbrido (calculate-price Edge Function):
    - Preço fixo por zona (500 Kz base + 150 Kz/km)
    - Surge pricing dinâmico (razão demanda/oferta)
    - Multiplicadores por veículo: Moto -40%, Comfort +40%, XL +80%
    - Exemplos:
      Centro → Talatona: ~2.500 Kz (~13 km)
      Viana → Centro: ~3.000 Kz (~18 km)

  Código relevante (zonePrice.ts):
    - ZONES: mapeamento de zonas de Luanda com coordenadas
    - getZonePrice(): lookup de preço por zona

2.3 PAGAMENTO (Multicaixa Express)
------------------------------------
  Edge Function: multicaixa-pay
  
  4 ações:
    - initiate_payment: Cria pedido de pagamento, idempotente
    - check_status: Verifica estado do pagamento
    - callback: Webhook com verificação HMAC, crédito atómico
    - withdrawal: Saque de motorista (mín. 1.000 Kz)

  Limites: 500 Kz mínimo, 500.000 Kz máximo
  
  Código relevante:
    - credit_wallet_atomic(): RPC que credita saldo de forma atómica
    - process_withdrawal(): RPC de saque
    - Verificação HMAC no callback (segurança)

2.4 IA ASSISTENTE (Kaze)
--------------------------
  Arquitetura multi-provider:
    - Google Gemini (principal)
    - OpenAI GPT-4o
    - Groq Llama 3.1 8B (fallback rápido)
    - OpenRouter
    - Anthropic Claude

  Funcionalidades:
    - Chat multi-turno com contexto da app
    - Pesquisa de locais em Luanda (Google Search grounding)
    - Insights espontâneos durante corridas
    - Simulação de ganhos para motoristas
    - Decisões autónomas (Vigilante Engine)
    - Revisão pós-corrida guiada por IA
    - Modo local (fallback offline com respostas pré-definidas)

  Sistema de quota: 10 mensagens por corrida completada

  Código relevante (geminiService.ts):
    - createKazeChat(): Factory de chat multi-turno
    - callProxy(): Chamada à Edge Function com cache de sessão
    - getLocalKazeResponse(): Fallback local offline

  DEPOIS (rápido):
    let cachedSession: { token: string; expiresAt: number } | null = null;

    async function callProxy(action, payload, timeoutMs = 30000) {
      let session;
      // Usar sessão cacheada se ainda válida (com margem de 60s)
      if (cachedSession && Date.now() < cachedSession.expiresAt - 60_000) {
        session = { access_token: cachedSession.token };
      } else {
        const { data: sessionData } = await supabase.auth.getSession();
        if (!sessionData?.session) {
          const { data: refreshData } = await supabase.auth.refreshSession();
          session = refreshData?.session;
        } else {
          session = sessionData.session;
        }
        cachedSession = {
          token: session.access_token,
          expiresAt: (session.expires_at ?? 0) * 1000,
        };
      }
      // ... fazer pedido
    }

  Impacto: ~500ms-1s poupados por pedido à IA

    async function checkIpRateLimit(ip) {
      const entry = ipCounters.get(ip);
      if (!entry || (now - entry.windowStart) > IP_WINDOW_MS) {

4.1 SEVERIDADE CRÍTICA
-----------------------

  [C1] RLS policy abre todas as corridas a todos os utilizadores
    Ficheiro: FIX_RLS_DEFINITIVO.sql (linha 26-28)
    Código:
      CREATE POLICY "rides: motorista vê TODAS no mapa"
      ON public.rides FOR SELECT
      USING (true);
    
    Problema: Qualquer utilizador autenticado (incluindo passageiros) pode
    ver TODAS as corridas de TODOS os utilizadores, incluindo endereços,
    nomes e dados financeiros.
    
    Correção necessária: Remover esta policy e usar a política restritiva
    de 20260422_fix_rides_rls_final.sql

  [C2] driver_locations com USING (true) para SELECT
    Ficheiro: FIX_RLS_DEFINITIVO.sql (linha 13-16)
    Código:
      CREATE POLICY "driver_manage_own_location"
      ON public.driver_locations FOR ALL
      USING (true)
      WITH CHECK (auth.uid() = driver_id);
    
    Problema: USING (true) permite a qualquer utilizador ler localizações
    de motoristas que NÃO estão disponíveis.

4.2 SEVERIDADE ALTA
--------------------

  [H1] Chaves de API no localStorage
    - KazePanel.tsx:459 → zenith_groq_api_key
    - KazePanel.tsx:317 → zenith_elevenlabs_api_key
    - aiModelSettings.ts:58 → zenith_ia_api_key_v2
    
    Problema: localStorage é acessível a qualquer JavaScript no mesmo
    origin. Um XSS pode exfiltrar estas chaves.

  [H2] VITE_ELEVENLABS_API_KEY no bundle do cliente
    - Ficheiro .env:17
    - Esta é uma chave SERVER-SIDE que não deve estar no frontend
    - Vite inclui todas as variáveis VITE_ no bundle JS

  [H3] KAZE_ALLOW_INSECURE_TLS=1 no .env
    - Desverifica certificados TLS
    - Vulnerável a ataques MITM

4.3 SEVERIDADE MÉDIA
---------------------

  [M1] ensure_user_exists chamável por qualquer utilizador autenticado
    - 20260420_critical_fixes.sql:138
    - GRANT EXECUTE TO authenticated
    - Pode criar registos de utilizador para IDs arbitrários

  [M2] 252+ chamadas console.log/warn/error em produção
    - Despejam informação de debug no browser console

  [M3] 60+ ficheiros SQL com correções RLS sobrepostas e conflitantes
    - Difícil manter e auditar
